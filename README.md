# Серверная программа клиент-серверной системы обработки данных (vcalc_server)

## 1. Описание проекта
Программный комплекс **vcalc_server** предназначен для сетевой аутентификации клиентов и вычисления среднего арифметического числовых векторов в соответствии с техническим заданием курсовой работы по дисциплине **«Технологии и методы программирования»** (ПГУ).

- **Разработчик:** Попков Вадим Сергеевич
- **Группа:** 25ПИ1
- **Язык разработки:** C++17
- **Сетевой протокол:** TCP/IP (сокеты Linux POSIX)
- **Криптография:** MD5 (библиотека Crypto++)

---

## 2. Архитектура и основные классы

Система декомпозирована на 6 специализированных модулей:

1. **\ref Server** — главный управляющий класс (диспетчер). Отвечает за парсинг параметров командной строки (`-b`, `-l`, `-p`, `-h`), инициализацию модулей, управление жизненным циклом и серверным циклом `while (s_running)` с обработкой сигналов `SIGINT`, `SIGTERM` и игнорированием `SIGPIPE`.
2. **\ref Communicator** — низкоуровневый сетевой модуль TCP. Создает серверный сокет (`bind`, `listen`), принимает соединения (`accept`), отправляет и принимает текстовые строки (`LOGIN`, `SALT16`, `"OK"`, `"ERR"`) и бинарные структуры векторов `uint32_t`.
3. **\ref UserDatabase** — модуль базы учетных записей. Загружает файл формата `LOGIN:PASSWORD`, парсит строки, отсекает комментарии `#` и пустые строки, предоставляет методы проверки пользователя `hasUser()` и получения пароля `getPassword()`.
4. **\ref Authenticator** — модуль криптографии. Генерирует 64-битное случайное число (строку `SALT16` из 16 hex-символов в верхнем регистре) и рассчитывает контрольный MD5-хеш: `MD5(SALT16 || PASSWORD)`.
5. **\ref DataProcessor** — вычислительный модуль. Вычисляет среднее арифметическое числовых векторов `uint32_t`. Для предотвращения целочисленного переполнения суммы использует 128-битный беззнаковый аккумулятор `__uint128_t` с ограничением `UINT32_MAX`.
6. **\ref Logger** — модуль ведения журнала работы. Записывает информационные события и ошибки в файл журнала в формате `[ГГГГ-ММ-ДД ЧЧ:ММ:СС] [УРОВЕНЬ] Сообщение`. Поддерживает автоматическое раскрытие домашней директории `~` и создание вложенных каталогов.

## 3. Сетевой протокол взаимодействия

1. Клиент устанавливает TCP-соединение на порт сервера (по умолчанию `33333`).
2. Клиент передает идентификатор `LOGIN`.
3. Сервер проверяет логин в базе:
   - Если пользователь не найден -> сервер отправляет "ERR" и закрывает сокет.
   - Если найден -> генерирует 16-значную шестнадцатеричную соль SALT16 и отправляет её клиенту.
4. Клиент вычисляет хэш MD5(SALT16 || PASSWORD) и передает его серверу.
5. Сервер вычисляет эталонный хеш по паролю из базы:
   - Если хеши не совпали -> сервер отправляет "ERR" и закрывает сокет.
   - Если совпали -> отправляет "OK" и переходит в бинарный режим.
6. **Бинарный сеанс:**
   - Клиент отправляет количество векторов $N$ (4 байта, `uint32_t`).
   - Для каждого вектора клиент передает размер $S$ (4 байта, `uint32_t`) и $S$ значений по 4 байта (`uint32_t`).
   - Сервер выполняет вычисления и возвращает результат (4 байта, `uint32_t`).
7. Завершение сеанса связи и закрытие клиентского сокета.

## 4. Сборка и тестирование

### Требования к зависимостям:
- Компилятор с поддержкой C++17 (`g++`)
- Библиотека утилит сборки `make`
- Криптографическая библиотека `Crypto++` (`cryptopp-devel` / `libcrypto++-dev`)
- Фреймворк модульного тестирования `UnitTest++` (`unittest-cpp-devel` / `libunittest++-dev`)
- Генератор документации `doxygen`

### Команды Makefile:
- `make` — сборка исполняемого файла сервера `vcalc_server`.
- `make test` — сборка и запуск модульных тестов `unit_tests`.
- `make functional_test` — запуск скрипта функционального тестирования `functional_test.sh`.
- `make doc` — автоматическая генерация документации через Doxygen.
- `make clean` — очистка объектных файлов, бинарников и каталога документации.
